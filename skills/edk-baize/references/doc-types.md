# 文档类型处理规则

## 三种文档类型

- **A. 规范类文档**：标准规范、需求、API 文档、技术手册、协议定义（有编号体系、Required/Optional 约束、逐项定义）
- **B. 观点类文档**：文章、博客、讨论、笔记、报道（表达观点、经验、分析）
- **C. 培训类文档**：教程、课程、操作指南、培训材料（教授如何做某事）

## ⛔ 第零步：测试用例素材路由

⛔ 在判断 A/B/C 文档类型之前，必须先完成测试用例识别。
详细判断规则和路由逻辑见 [ingest-details.md](ingest-details.md) 的"第零步"章节，此处不重复定义。

若素材被认定为测试用例 → 路由到 edk-baize-tests，不走 A/B/C 流程。

## 内容拆分原则（核心）

⛔ 一篇素材消化后产出的页面**应该按内容形态分散到不同子目录**，而不是塞进一个巨大的概念页：

| 素材中的内容形态 | 落地位置 | 模板 |
|----------------|---------|------|
| 名词定义、原理解释、为什么这样设计 | concepts/ | concept-template.md |
| 具体事物的属性、字段、版本、API 端点 | entities/ | entity-template.md |
| 有顺序的步骤、配置流程、安装指南 | procedures/ | procedure-template.md |
| 校验规则、状态转换、决策表、约束条件 | rules/ | rule-template.md |
| 多对象比较 | comparisons/ | comparison-template.md |

⛔ 拆分判断：

- 概念里如果出现"步骤 1 / 步骤 2 / 步骤 3" → 必须拆出 procedure
- 概念里如果出现"状态 A → 状态 B 当条件满足时" → 必须拆出 rule
- 概念里如果出现完整的字段表（5 个字段以上、有约束条件） → 考虑拆出 entity
- 单篇概念页超过 150 行 → 复审是否应拆分

⛔ ingest 阶段必须输出"内容拆分计划"给用户确认（除非素材极小或单一形态），格式：

```
📋 内容拆分计划：

来自素材 [{素材名}]：
- concepts/{名}.md      ← 定义和原理
- procedures/{名}.md     ← 配置步骤（步骤 1-N）
- rules/{名}.md          ← 状态转换 / 校验规则
- entities/{名}.md       ← 具体数据表 / API

确认后继续？
```

## 摘要页通用约束

⛔ 以下约束适用于所有类型的摘要页：

1. 填充内容到 `wiki/{Topic}/summaries/`
2. 规范类：核心观点必须按章节逐一覆盖；"文档结构"章节每个主要章节后必须有 `[[页面链接]]`（concept / procedure / rule 任一种皆可）
3. 培训类："知识模块"章节每个模块后必须有 `[[页面链接]]`
4. 溯源来源格式：`[[raw/{subdir}/{文件名}|显示名]]`（Obsidian wiki link），禁止纯文本或相对路径链接
5. 每个关键事实后面标注来源：`([[raw/{subdir}/{文件名}|源文, L42-45]])`
6. 数字和结论必须原文引用，不要用 AI 的话重述：
   - ❌ 差：该公司营收约 10 亿
   - ✅ 好：该公司营收"10.3 亿元"(raw/report.md, L128)

## 内容处理通用约束

- 必须先读取对应模板（concept/entity/procedure/rule），严格按模板章节结构输出
- 底部关联章节顺序见 `SKILL.md` 的"底部关联章节"表
- 溯源来源格式：`[[摘要页名]]`（禁止纯文本或相对路径）
- ⛔ **拆分判断必须询问用户**：遇到多内容形态、需要拆出 procedure/rule、与已有页面重叠时，必须暂停展示拆分计划，等待用户决定后才继续
- ⛔ **合并判断必须询问用户**：遇到多章节合并、内容拆分、与已有页面重叠时，必须暂停展示方案，等待用户决定

格式：
```
⚠️ 拆分/合并判断：
- 方案 A：...
- 方案 B：...
请选择。
```

## A. 规范类文档

### 摘要页

1. 读取 `assets/summary-spec-template.md`
2. 遵守"摘要页通用约束"

### 内容处理

⛔ 不可用观点类的"提炼几个要点"方式处理：

- 规范的每个章节都是独立的知识单元，必须为每个主要技术模块创建独立页面
- 每个章节按"内容拆分原则"决定落到 concepts/entities/procedures/rules
- 不适用简化处理（规范类文档通常都 > 1000 字）
- 处理步骤：
  1. 按文档大纲，输出"内容拆分计划"给用户确认
  2. 用户确认后，逐一创建对应页面（读取对应模板）
  3. 更新 `wiki/{Topic}/index.md`，按页面类型分组列出
  4. 更新 `wiki/{Topic}/overview.md`
- 遵守"内容处理通用约束"

## B. 观点类文档

### 摘要页

1. 读取 `assets/summary-template.md`
2. 遵守"摘要页通用约束"

### 内容处理

**完整处理**（素材 > 1000 字）：
1. 提取 3-10 个关键概念
2. 输出"内容拆分计划"
3. 检查是否需要创建新的实体页（entities/）
4. 检查是否需要创建概念页（concepts/）— 围绕"思想/方法论/模式"
5. 如果素材包含可执行步骤 → 创建 procedures/ 页面
6. 如果素材包含约束/规则 → 创建 rules/ 页面
7. 更新 `wiki/{Topic}/overview.md`（如果知识库全貌有变化）

**简化处理**（素材 < 1000 字）：
1. 提取 1-3 个关键概念
2. 如果关键概念已有页面，追加信息；否则标记 `[待创建]`
3. 跳过 overview 更新

遵守"内容处理通用约束"。

## C. 培训类文档

### 摘要页

1. 读取 `assets/summary-training-template.md`
2. 遵守"摘要页通用约束"

### 内容处理

**完整处理**（素材 > 1000 字）：
1. 按知识模块提取关键概念
2. 输出"内容拆分计划"
3. 培训材料的常见落地形态：
   - **操作流程**（procedures/）：完整的步骤序列，最常见
   - **常见问题**（concepts/ 或 rules/）：教程中提到的坑和解决方案
   - **工具/命令**（entities/）：关键工具的用法速查
   - **最佳实践**（concepts/）：从教程中提炼的推荐做法
4. 可适度压缩相似步骤，但不可丢失关键操作细节
5. 更新 `wiki/{Topic}/overview.md`

**简化处理**（素材 < 1000 字）：
1. 提取 1-3 个关键操作/知识点
2. 如果已有页面，追加信息；否则标记 `[待创建]`
3. 跳过 overview 更新

遵守"内容处理通用约束"。
